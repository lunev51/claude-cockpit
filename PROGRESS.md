## Что работает

Кокпит отдаёт свой интерфейс по сети. Браузер на другой машине **подключается** к
живым вкладкам (не создаёт новые), видит историю вывода, печатает в терминал,
видит агентов и слэш-команды.

План 2 добавил к этому:

- **Трей.** Крестик прячет окно, а не завершает кокпит; выход — только пунктом меню.
  В меню видно, где сейчас управление, и адрес для браузера. Иконка приглушается,
  когда рулит другая машина.
- **Автозапуск** при входе в Windows (галочка в меню трея, по умолчанию выключена).
  Окно при этом не показывается — кокпит поднимается сразу в трей и восстанавливает
  вкладки.
- **Эстафета управления.** Один хозяин в каждый момент: открыл страницу в браузере —
  забрал руль, окно ПК спряталось; показал окно из трея — забрал обратно. Невладелец
  видит заглушку и может смотреть (статусы, лимиты, дашборд, поиск истории), но не
  писать. Размер терминала передаётся при пересадке — «плывущий масштаб» лечится этим.
- **Обрыв связи виден и лечится сам**: «Нет связи с кокпитом», переподключение с
  нарастающим интервалом, затем перезагрузка страницы. Сессии на ПК не трогаются.

Ключевые файлы плана 2: `src/main/{ownership,write-channels,tray-menu,autostart}.js`,
проводка — `createHandoffWiring` в `ipc.js`, интерфейс — `src/renderer/js/handoff-view.js`
и обвязка в `app.js`/`api-boot.js`.

## ЖДЁТ ЖИВОЙ ПРОВЕРКИ (когда будет макбук под рукой)

План 2 принят пользователем 05.08: «с мака всё работает, эстафета тоже». Осталась
одна жалоба и два фикса на неё, **не проверенные вживую** (PR #26, `bf9725e`):

> при возврате управления на ПК картинка разъезжается, приходится менять размер
> окна руками, чтобы всё отрисовалось

Починено с двух сторон: владение теперь помнит АКТУАЛЬНЫЙ размер (раньше знало его
только с момента захвата, а ресайзы окна шли мимо), и получение управления
принудительно пересчитывает геометрию активной вкладки (`ResizeObserver` молчит,
когда контейнер не менялся).

**Что спросить у пользователя при проверке:** если разъезжается до сих пор — сразу
после возврата или уже после переключения вкладки? Это разные пути: второй
намеренно оставлен наблюдателю за размером контейнера.

Тем же PR #25 (`fd5d996`) починена вставка — она была мертва целиком: обработчик
разрешений отклонял `clipboard-read`. `Ctrl+V` теперь вставляет наравне с
`Ctrl+Shift+V`. Проверено пользователем на ПК.

## Известные ограничения

- Вкладки, открытые другим клиентом, не приезжают сами — подхватываются при получении
  управления (события `tabs:changed` в форме api нет).
- `Ctrl+Tab` в браузере недоступен, переключение вкладок — по номеру.
- `Cmd+W` закроет вкладку с кокпитом, перехватить нельзя.
- Спящий ПК недоступен: Tailscale его не разбудит.

## Помнить

- `Select-Object -First N` в конвейере со `npm run smoke` обрывает поток и роняет
  процесс: код выхода получается ненулевым при полностью успешном прогоне.

  (`git worktree` + junction на `node_modules`), а не в рабочем.

  PowerShell — сообщение писать файлом и `git commit -F`.
