# Общее ревью кода (09.08.2026)

Семь независимых ревьюеров на Fable 5, по непересекающимся областям, read-only.
58 находок. Ниже — сведённый и отсортированный список; помечено, что проверено
лично по коду после отчётов (агентам на слово не верили).

Формат: **что** — где — почему важно.

---

## A. Чинить в первую очередь

### A1. `statSync` без try роняет весь процесс ✔проверено
`src/main/net-server.js:136` — `fs.existsSync(abs) && fs.statSync(abs).isFile()`.
Между двумя вызовами файл может исчезнуть (пересборка, антивирус, npm install),
а на Windows `statSync` умеет бросать EPERM и на существующем файле. Исключение
уходит в `uncaughtException` → `app.exit(1)` со всеми pty открытых вкладок.
В этом же файле дважды чинили ровно этот класс (битый `%`-escape, ошибка потока
чтения) — путь статики остался последним незакрытым.
Фикс: один `try { st = fs.statSync(abs) } catch { continue }` (заодно вдвое
меньше системных вызовов).

### A2. Нет предела размера кадра WebSocket ✔проверено
`src/main/net-server.js:330` — `maxPayload` не задан, дефолт `ws` = 100 МиБ.
Один кадр держит в памяти буфер + строку + результат разбора — сотни мегабайт
на машине с 8 ГБ. Фикс: явный `maxPayload` (16 МиБ с запасом на голосовые
кадры); при превышении `ws` сам закрывает соединение, клиент переподключится и
доберёт хвост через `net:buffer`.

### A3. Два `npx ccusage` всё ещё параллельно ✔ПОЧИНЕНО (PR к A3)
`src/main/usage-ccusage.js:185` — `Promise.all([...])`. По замерам в соседнем
комментарии пик двух прогонов ~485 МБ против ~240 МБ у одного. Это остаток
инцидента «вешает комп»: флаги добавили, параллельность оставили.
Сделано: два последовательных `await`; провал первого не запускает второй.
**Отложено:** троттлинг повторных провальных попыток — при сломанном ccusage
каждое открытие дашборда после TTL по-прежнему запускает полный тяжёлый
daily-прогон (до 60 с чтения транскриптов). Ранний выход срезает только второй.

### A3-бис. Вееры внешних процессов: до 20 `gh` и до 50 `git` разом ✔найдено при ревью фикса A3
Тот же класс, что A3, но крупнее:
- `gh-info.js:370` — `Promise.all(prsParsed.map(enrichPrChecks))`, до 20
  одновременных `gh pr view`, каждый под `shell:true` (на Windows это до 40
  процессов). Срабатывает при протухании глобального кэша, то есть на каждом
  открытии дашборда реже 150 с.
- `gh-info.js:338` — 3 параллельных `gh` (search prs + search issues + api).
- `git-info.js:350` — до 50 параллельных `git` для untracked-диффов.
- `app.js:3015` — тик раз в 3 минуты бьёт `refreshTabPr` по всем вкладкам разом,
  и TTL кэша (150 с) намеренно меньше периода, то есть спавны реальные (это же
  B7 — в скрытом окне они бессмысленны вдвойне).
Просится общий пул/очередь на внешние процессы.

### A4. `config.user.json` пишется неатомарно ✔проверено
`src/main/config.js:158` — голый `writeFileSync`, тогда как рецепты
(`recipes.js:139`) и журнал ночной смены пишутся через temp+rename с `.bak`.
`setConfig` зовётся на каждый Ctrl+G и клик. Обрыв посреди записи → битый файл →
`readJson` вернёт `{}` → разом теряются все настройки, включая сетевой доступ.

### A5. TDZ-мина: `outputBuffer` объявлен на 200 строк ниже использования ✔проверено
`src/main/ipc.js:1457` использует, `1672` объявляет. Работает только потому, что
события в этот промежуток не приходят синхронно. От этого же класса `broadcast`
перенесли в начало (`1304`) с отдельным комментарием — для `outputBuffer` приём
не применили. Любая будущая правка, эмитящая `term:data` синхронно, роняет
кокпит на старте, причём только в проде (registerIpc не тестируется).

### A6. Страж реестра каналов имеет двойной люфт ✔проверено
`test/command-registry.coverage.test.js:11` читает **только** `ipc.js`, тогда как
симметричный `broadcast-guard.test.js:33` обходит весь `src/main`. И порог
`>= 43` (строка 42) при **49** реальных регистрациях — до шести каналов можно
удалить, прогон останется зелёным.
Чем опасно: прямой `ipcMain.handle` в `main.js` пройдёт мимо стража, а заодно
мимо гарда владения — локальное окно сможет писать в обход эстафеты.
Фикс: сканировать весь `src/main`; порог заменить точной сверкой с `API_SHAPE`
плюс явный список сетевых каналов.

### A7. Ночная смена: будильник не переживает сон машины
`src/main/night-watch.js:167` — единственный длинный `setTimeout`. Блокер держит
от автосна, но не от ручного «Сон», крышки и гибернации; поведение длинных
таймеров после resume на Windows недетерминировано. Отказ тихий: в журнале
`armed` и больше ничего.
Рядом: окно ретраев ~16 минут (3 × 5 мин, `night-watch.js:541`) — любой ночной
транзиент длиннее съедает всю ночь, после `gave-up` машина ещё и засыпает.
Фикс: грубый сторож-интервал 60 с (`doWake` уже идемпотентен) + подписка на
`powerMonitor 'resume'`; ретраи с прогрессивным бэкоффом.
Замечание: фича боевой приёмки ещё не проходила — цена отказа максимальная.

## B. Заметно в повседневной работе

### B1. «Перезапустить сессию» в палитре без гарда ✔проверено
`src/renderer/js/app.js:1764` — `run: () => window.api.term.restart(activeId)`.
Кнопка ⟳ (добавлена 09.08) проверяет управление и объясняет отказ тостом, а
палитра шлёт напрямую: у невладельца — молчание. В комментарии к кнопке
написано «отдельной логики перезапуска не заводим» — она заведена.
Фикс: вынести `restartActiveSession()` и звать из обеих точек.

### B2. Запасное копирование крадёт фокус ✔проверено
`src/renderer/js/clipboard.js:48` — `area.focus()`, а в `finally` только
`area.remove()`. Фокус падает на `body`. Это основной путь в браузере (по http
Clipboard API недоступен), а «копировать выделением» включено по умолчанию —
после каждого копирования с мака клавиатура не попадает в терминал до клика.
Хвост фикса от 09.08.

### B3. Тост врёт про буфер обмена ✔проверено
`src/renderer/js/api-boot.js:152` — сообщение «она в буфере обмена» уходит
**до** попытки записи, а `navigator.clipboard` в http-контексте недоступен, то
есть фраза ложна ровно в том сценарии, ради которого написана. Рядом лежит
рабочий `copyText()` — не переиспользован.

### B4. Потеря управления не закрывает палитру, peek и мини-форму
`src/renderer/js/app.js:2448` — `afterControlLost()` убирает только оверлей
восстановления. Открытая палитра переживает смену владельца, и действия из неё
потом отклоняются молча (а «удалить воркспейс» — ещё и unhandled rejection).

### B5. Сверка вкладок теряет событие, пришедшее во время сверки
`src/renderer/js/app.js:859` — `if (tabsSyncRun) return tabsSyncRun;` без флага
«прибежало ещё». Снимок берётся в начале, прогон долгий (история по каждой
вкладке). Событие соседа внутри окна теряется до следующего `tabs:changed`.
Это класс, уже дважды дававший живые жалобы (08.08 и 09.08).

### B6. `start()` при резюме не сбрасывает `sessionBound` ✔проверено
`src/main/sessions.js:551` против `restart()` на `664` (там сброс есть, помечен
«FIX 3»). Из-за асимметрии провал резюма на этом пути не детектится: не сработают
ни обнуление протухшего `sessionId`, ни авто-восстановление, и мёртвый id
уезжает в манифест — следующий запуск снова резюмит мертвеца.

### B7. Опрос `gh` по всем вкладкам каждые 3 минуты в скрытом окне ✔проверено
`src/renderer/js/app.js:3015`. TTL кэша (150 с) намеренно меньше периода, то есть
каждый тик — реальные спавны `gh` по числу вкладок. Окно в трее делает это
часами, бейджи при этом никто не видит. Кольца там же перерисовываются каждые 30 с.
Фикс: гейт `document.hidden` + догон по `visibilitychange`.

### B8. Личный путь машины в дефолтах публичного репозитория ✔проверено
`src/main/config.js:149` — `'C:\\Users\\Lunev\\AssistClaude\\claude-companion'`.
Место такому пути — в локальном `config.user.json`, механизм оверлея для этого и
существует.

### B9. Очередь промптов невидима переподключившемуся клиенту
`src/main/sessions.js:1088` — `list()` не отдаёт очередь, а renderer собирает её
только из событий `queue:changed`. После перезагрузки страницы очередь выглядит
пустой, человек добавляет промпты повторно — двойной вброс на следующих Stop.
Для `waitingText` этот же пробел уже закрывали добавлением поля в `list()`.

### B10. Поиск истории читает всё хранилище без отмены и потолка
`src/main/history-index.js:300` — каждый запрос стримит транскрипты заново
(~1.7 ГБ по замеру проекта), останов только при 50 результатах, отмены нет.
Уточнение запроса даёт параллельные полные проходы по диску.

### B11. Голосовой ввод в браузере не работает вовсе ✔ПРИНЯТО КАК ОГРАНИЧЕНИЕ (10.08)
**Решение владельца: не чинить** — голосом с макбука он не пользуется. Записано
в «Известные ограничения» PROGRESS.md. Чтобы это не выглядело поломкой, в
браузере удержание клавиши голоса сразу говорит, что голос доступен только в
окне на ПК, — вместо прежнего «неверный формат WAV», уводившего в сторону.
Если понадобится: нужен транспорт для бинаря — base64 в кадре (30 с ≈ 1,3 МБ,
потолок кадра это переживёт) либо отдельный бинарный кадр WebSocket.

`recorder.js:106` отдаёт **ArrayBuffer**, а транспорт `net-api.js:60` делает
`JSON.stringify({id, channel, args})` — у ArrayBuffer нет перечислимых свойств,
и на провод уходит `{}`. Сервер получает пустой объект, `ipc.js:994` не узнаёт
формат и возвращает «неверный формат WAV». То есть push-to-talk с макбука не
просто тихий — он не отправляет ни байта, и человек видит только тост об
ошибке формата.
Починка: слать base64 (30 с записи ≈ 1,3 МБ — потолок кадра не мешает) или
бинарный кадр отдельным путём.

### B8-бис. Личные пути остались в тестах и документации ✔найдено при ревью фикса B8
Страж `test/no-personal-paths.test.js` сканирует `src/`, `scripts/` и корневые
конфиги — там чисто. Но репозиторий публичный целиком, а личные пути живут ещё:

- **`test/`** — десятки литералов вида `C:\Users\<имя>\helper` в фикстурах
  (`browse-view.test.js`, `history-index.test.js`). Это тот же класс, что B8;
  чинится заменой фикстур на нейтральные и расширением стража на `test/`.
- **`docs/` и `PROGRESS.md`** — плотно, включая сам этот отчёт. Тут нужна
  политика: чистить или осознанно принять (документы описывают конкретную
  машину владельца). Сканировать `.md` стражем без списка исключений нельзя —
  утонет в легитимных примерах.
- **Комментарии в `src/`** — страж их намеренно пропускает, но довод B8
  («утечка структуры чужого диска») к ним применим: `pty.js`, `stt.js`,
  `browse-view.js` публикуют тот же путь. Дёшево обезличить до `C:\Users\<you>\`.

### B10-бис. Оценка объёма хранилища в комментарии завышена ✔уточнено при ревью фикса
Индекс истории намеренно нерекурсивный: читаются только транскрипты верхнего
уровня (`~/.claude/projects/*/*.jsonl`), а это 49 файлов, не 1194. Суб-агентские
транскрипты (~1145 файлов) поиск не читал и раньше. Потолок в 400 сессий сегодня
не срабатывает вовсе — он задел на будущее, а реальную экономию даёт отмена
устаревшего прохода.

## C. Гигиена и мелочи

Сеть и эстафета:
- `ownership.claim` не валидирует размер, хотя соседний `noteSize` валидирует —
  мусорный `{cols: undefined}` оседает в карте (`ownership.js:26`). ✔проверено
- `sizes` растёт с каждым переподключением и не чистится (`ownership.js:23`).
- `net:buffer`, `owner:claim`, `owner:get` обрабатываются до реестра — гард на них
  не зовётся никогда (`net-server.js:227`). Сегодня безопасно (все FREE), но
  инвариант «путей в обход нет» держится на совпадении. Нужен тест-инвариант.
- Повторная регистрация канала молча перезаписывает карту; в тестах фейковый
  `ipcMain` не бросит (`command-registry.js:28`).
- Белый список Host всегда с портом — на `port: 80` браузер шлёт Host без него,
  все WS-апгрейды получают 403 (`net-server.js:292`).
- Каждое событие сериализуется отдельно для каждого клиента (`net-server.js:341`).
- `reply` шлёт ответ и на кадры без `id`, хотя ветки ошибок это гардят.

Интерфейс:
- Панель диффа пересобирает до ~2200 узлов каждые 1.5-3 с даже при неизменном
  диффе, сбрасывая прокрутку (`diffpanel.js:345`).
- Дашборд полностью пересобирается каждые 30 с ради строки «сброс через …»,
  сбрасывая hover под курсором (`dashboard.js:648`).
- Кнопки панели поиска терминала без `mousedown`-preventDefault — после клика
  мышью Esc и Enter мертвы (`terminal.js:195`).
- Esc в палитре и поиске истории умирает, если фокус ушёл кликом по паддингу
  панели (`palette.js:93`, `search.js:245`). Три разные Esc-дисциплины на один
  класс оверлеев.
- `dispose()` терминала не гасит `resizeTimer`/`persistTimer` (`terminal.js:444`).
- Шпаргалка не знает про Ctrl+«+»/«−»/«0», Ctrl+колесо и про то, что вставка
  работает обычным Ctrl+V (`hotkeys.js:33`).
- Дубли чистых функций: `formatTime` ≡ `formatClock`, `colorFor` в двух файлах с
  одинаковыми порогами 60/85 — разъедутся молча.
- `addon-webgl` и `addon-unicode11` (~300 КБ) грузятся всегда, хотя обе фичи
  выключены по умолчанию (`index.html:18`).
- `toggleNight` без single-flight: двойной клик по 🌙 возвращает исходное
  состояние, человек считает, что включил (`app.js:636`).
- Отказ IPC при открытии дашборда затирает валидный `lastUsage`, и кольца
  показывают прочерки (`app.js:534`).
- Слушатель «окно вернуло фокус → пометить прочитанным» живёт внутри
  `bindVoiceHotkey` (`app.js:1334`) — не его дело.
- Мёртвые поля `entry.lastPtyStatus` и `entry.fontSize` — пишутся, не читаются.

Периферия и проводка:
- `usage-oauth` пишет кэш на диск каждые 3 минуты, даже когда данные не менялись
  (~480 записей в сутки).
- `history-index` переписывает кэш целиком на каждый refresh, даже если ни один
  файл не изменился.
- Три независимых пути к `usagePoller.refresh()` с двумя разными single-flight и
  без общего рубежа (`ipc.js:1528` и `1771`) — параллельные запросы возможны,
  при том что от 429 оборонялись три круга ревью. ✔проверено
- Литерал `'working'` в `nightWatch.onTabStop` обязателен, но нигде не объяснён —
  добросовестный рефакторинг «передавать настоящий prev» убьёт детект
  лимит-стопа для 'stuck' (`ipc.js:1477`).
- `manager.list().find` повторён семь раз, дважды в одном событии; `list()` при
  каждом вызове клонирует все вкладки.
- Каскады `dispose` без пошаговых try/catch — одно исключение оставляет живые
  `claude.exe` и whisper-server (`ipc.js:2316`, `main.js:656`).
- Обёртка `setTimer`-с-unref продублирована дословно дважды.
- `history:refresh` отдаёт наружу весь индекс, хотя нужен счётчик.
- Первое скрытие окна крестиком ничем не объясняется, хотя комментарий у
  `hideExplained` обещает обратное (`main.js:201`).
- Комментарий в шапке `attach-guards.js` описывает ядро ДО фикса резюма — главная
  заявленная причина гарда больше не верна.
- Фикстуры `'C:\proj\alpha'` с одинарными бэкслэшами дают `'C:projalpha'`
  (`test/sessions.test.js:1966`) — сегодня безвредно, опасно при копипасте.

## Что ревьюеры отметили как сильное

Комментарии-леджер: почти каждое неочевидное решение несёт причину, номер находки
ревью и живой замер. Дисциплина гонок (три разных механизма поколений в
`sessions.js` под три класса гонок). Вынос чистой логики в тестируемые модули при
нетестируемом Electron. Уроки инцидента 8 ГБ вшиты в код, а не остались в
переписке. Дефолт-deny в `write-channels` с тестом полноты. Инкрементальный
рендер сайдбара — полных перерисовок нет. Все девять оверлеев зарегистрированы в
`overlayFlags()`. Фикстуры тестов — реальные образцы с этой машины.

Отдельно: обе исторические дыры закрыты по-настоящему — `fakeManager` теперь сам
бросает на фикстуре без `tabId`, а страж `registerIpc` связывает объявление с
использованием. Классических холостых тестов ревьюер не нашёл.
