## Первым коммитом Фазы 2b (рекомендация финального ревьюера)

1. **Bind-session на любом cwd-fallback**: сейчас `bindSession` только на SessionStart —
   поздние события старой сессии после restart() могут через cwd-fallback штамповать
   новую вкладку старым статусом. Фикс: в hook-bridge при cwd-fallback биндить
   `data.session_id` для ЛЮБОГО события (стабилизирует маршрутизацию после первого же).
2. **Удалять bridge-port при stopBridge()**: после выхода кокпита хуки продолжают
   POST-ить на мёртвый порт; если порт займёт другой процесс — он получит текст промптов
   (UserPromptSubmit). Одна строка: unlink в stop.
3. **uncaughtException-guard в cockpit-hook.js**: `process.on('uncaughtException',
   () => process.exit(0))` сверху — контракт «всегда exit 0» становится безусловным
   (сейчас error на stdin-стриме теоретически даёт exit 1).
4. **Spawn-тест хук-скрипта**: child_process + стаб-сервер — зафиксировать wire-контракт
   (единственный компонент без автотеста; финальный ревьюер гонял руками).

## Учесть в дизайне 2b

5. **Статус idle обязан закрыть false-positive «завис»**: вкладка, просто стоящая у
   промпта без ввода, через 5 мин уходит в stuck («нет вывода 5м») в секцию Проблемы.
   При введении idle: armить stuck-детект только после хук-событий активности,
   или переводить done/пост-Stop-вкладки в idle, исключённый из checkStuck.
