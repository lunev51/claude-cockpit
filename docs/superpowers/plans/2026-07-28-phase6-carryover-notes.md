# Carryover из финального ревью Фазы 5 → в Фазу 6

Источник: whole-branch review ветки phase5-usage (9488179..20e364d). Все четыре Important
(карточка «Расход» показывала all-time вместо 30 дней, расходы не обновлялись и не показывали
возраст, безусловная блокировка Ctrl+R ломала хоткей во вкладках, Escape поверх дашборда
отменял восстановление воркспейса) закрыты фикс-волной 20e364d. Ниже — отложенное.

## Взять в работу

1. **Единый стек оверлеев.** Сейчас четыре независимых обработчика Escape на `document` в
   capture-фазе (restore, dashboard, palette, peek), и порядок между ними держится на порядке
   регистрации. Точечный гард в restore-оверлее закрывает найденный сценарий, но класс багов
   остаётся: два оверлея могут быть открыты одновременно (peek z40 рисуется поверх dashboard
   z32), а `openPeek` дашборд не гасит. Нужен один владелец Escape и стек с приоритетом.
2. **Тестируемость проводки usage в `ipc.js`.** Всё написано инлайн внутри `registerIpc` и
   потому не покрыто ничем: `usageBroadcastKey`, 5-секундный сторож, single-flight + порог 10 с,
   smoke-гейт. Это ровно тот код, который правился по ревью дважды. Вынести в чистые функции —
   тесты появятся без всякого Electron. Отдельно стоит тест «в IPC-payload нет ничего, кроме
   белого списка полей» (адверсариальный тест есть только на путь логов).
3. **`spend.byModel` считается, кэшируется и никогда не рисуется** — либо показать разбивку
   расходов по моделям (полезнее, чем `weekly_scoped`, который сейчас 0%), либо убрать из слоя.
4. **Осиротевшие процессы npx.** `execFile('npx', …, {shell:true, timeout:60000})` при таймауте
   убивает `cmd.exe`, но не порождённый им node; `disposeSessions()` висящие execFile не трогает.
   Частота низкая, но на Windows это классические грабли — стоит хранить ссылки и убивать дерево.
5. **Пин версии ccusage.** `npx --yes ccusage@latest` при каждом промахе кэша тянет и исполняет
   последнюю версию из npm — латентность и supply-chain-поверхность. Пин `ccusage@20.0.19`
   даст скорость и предсказуемость.
6. **429-бэкофф не переживает перезапуск** (`nextAllowedAt` только в памяти) — каждый старт
   даёт один запрос сверх гейта. Три строки: положить в кэш-файл рядом с `lastGood`.
7. **Нет single-flight у `ccusage.get()`**: IPC защищает refresh от refresh, но не get от
   refresh — до четырёх параллельных npx. Флаг «в полёте» внутри модуля.
8. **Бейдж «данные устарели» приписан секции лимитов**, даже когда устарели только расходы —
   ошибается в безопасную сторону, но логичнее два независимых маркера.
9. **Устаревшее 5-часовое кольцо** может показывать красные 87% при уже случившемся сбросе
   («красное 87% / сброс через —» противоречиво). При `stale && resetsAt < now` показывать «—».
10. **Мелочи дашборда:** «сброс через —» читается коряво при `resetsAt: null` (у weekly_scoped
    он именно такой); `p.name === undefined` даёт строку «undefined» (достижимо только через
    руками испорченный кэш); `refreshBtn`/`refreshing` живут на уровне замыкания, а не сессии
    открытия — при закрытии во время обновления и быстром переоткрытии первый промис может
    сбросить кнопку второй сессии (косметика, сеть защищена отдельным флагом).

## Предупредить пользователя (не баг, но мышечная память)

- **Ctrl+D теперь открывает дашборд** и больше не доходит до Claude Code, где это «выход».
  Решение осознанное и задокументировано, но сказать стоит явно.
- **Ctrl+R и F5 снова работают** внутри вкладок: гард убран, потому что живая проверка
  показала, что он структурно не мог перехватить reload из DevTools (клавиша уходит в
  отдельный webContents девтулзов), зато ломал рабочий хоткей во всех вкладках.

## Проверено и признано нормой

- Токен-путь герметичен: файл → заголовок, и всё. В кэш пишется только `lastGood` без токена,
  в IPC — только снапшот, все вызовы `log` обёрнуты санитайзером (есть адверсариальный тест,
  где сообщение чужой ошибки само содержит токен).
- Инъекций через `shell:true` нет: все аргументы npx — литералы.
- Таймеры (5 с сторож, 30 с отсчёт, поллер) — `unref` и гасятся в `disposeSessions()`.
- Ревьюер прогнал `dashboard.js`/`rings.js` на DOM-стабе по 8 формам данных (null payload,
  ok:false, percent undefined, нулевые сессии, пустой byDay) — ни исключений, ни NaN.

## Ручная приёмка Фазы 5 (за пользователем)

1. Кольца в подвале сайдбара: проценты сверить с `/usage` в терминале, отсчёт — правдоподобный.
2. Ctrl+D: «Расход за 30 дней» должен быть сопоставим с суммой столбиков графика (а не в сотни
   раз больше), видно «обновлено в HH:MM», таблица проектов скроллится, 7д/30д переключаются.
3. Отключить сеть → кольца тускнеют, появляется «данные устарели», приложение не падает.
