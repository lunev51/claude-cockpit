# Cockpit Phase 7 — Очередь, поиск, рецепты, воркспейсы (финальная фаза спеки)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Закрыть оставшиеся фичи спеки: очередь промптов (печатать, пока Claude занят), глобальный поиск по истории всех сессий, библиотека параметризованных промптов и именованные воркспейсы. Плюс хвосты ревью фазы 6.

**Architecture:** Очередь живёт в `sessions.js` (уже есть поле `queue` в описании вкладки из спеки §4.1) и вбрасывается по Stop-хуку. Поиск — БЕЗ SQLite (нативные модули ломают пребилды pty): собственный индекс по JSONL-транскриптам в обычном JSON-файле + потоковый дочит файлов при запросе. Рецепты и воркспейсы — конфиг-файлы в userData, интеграция через палитру.

**Спека:** §3.12 (очередь), §3.18 (поиск), фичи 27 (библиотека промптов) и 28 (именованные воркспейсы).
**Carryover фазы 6:** `docs/superpowers/plans/2026-07-28-phase7-carryover-notes.md` — пункты 1-5 и замечание пользователя про блёклый бейдж закрываются в Task 5.

**Голосовой ввод (§25) в эту фазу НЕ входит — осознанно.** Лучшее решение не требует кода: системная утилита (Wispr Flow) работает во всех приложениях сразу, включая кокпит. Портирование whisper-стека из Companion имеет смысл только если пользователь захочет офлайн/приватный вариант — это отдельный разговор, а не задача фазы.

## Global Constraints

- Никаких новых npm-зависимостей и НИКАКИХ нативных модулей (better-sqlite3 сломает пребилды node-pty).
- Все внешние вызовы и файловый ввод-вывод — через инжектируемые зависимости; логика в чистых модулях, тесты `node --test`.
- Никогда не бросать наружу; отсутствие данных — нормальное состояние, а не ошибка.
- Транскрипты Claude Code (`~/.claude/projects/**/*.jsonl`) читаем ТОЛЬКО на чтение; формат внутренний и меняется между версиями — парсер обязан переживать неизвестные поля и битые строки.
- В smoke не читать транскрипты и не спавнить процессы.
- Палитра — только токены v2.
- `/F` в `taskkill`: запрещён для завершения САМОГО приложения в проверках; для уборки helper-процессов в продакшн-коде разрешён (правило уточнено в фазе 6).
- Каждая задача: `npm test` + `npm run smoke` (exit 0) → commit. Комментарии по-русски. Работать СИНХРОННО, без фоновых прогонов.

### Task 1: Очередь промптов (TDD)

**Files:** Modify `src/main/sessions.js`, `src/main/ipc.js`, `src/preload/preload.js`, `src/renderer/js/app.js`, `index.html`, `app.css`; Test `test/sessions.test.js`

**Interfaces:**
- `sessions.js`: у вкладки появляется `queue: string[]`.
  - `enqueue(tabId, text)` → добавляет в конец, эмитит `queue:changed {tabId, queue}`; пустой/пробельный текст игнорируется.
  - `dequeueAll(tabId)` / `removeFromQueue(tabId, index)` / `clearQueue(tabId)` — управление, каждое эмитит `queue:changed`.
  - В `applyHookEvent` на `Stop`: если очередь непуста — взять ПЕРВЫЙ элемент, записать в pty (`tab.proc.write(text + '\r')`), убрать из очереди, эмитить `queue:changed`. Статус при этом станет `working` по следующему хуку — не подделывать.
  - Очередь очищается при `close`, НЕ переживает рестарт вкладки (это ввод для конкретной сессии) — но сохраняется при обычном переключении вкладок.
- IPC: `queue:add (tabId, text)`, `queue:remove (tabId, index)`, `queue:clear (tabId)`; событие `queue:changed`. preload: `queue.add/remove/clear/onChanged`.
- UI: под терминалом (внутри `#main`, НАД панелью действий) — компактная строка очереди: при пустой очереди скрыта; при непустой показывает чипы «1 · текст ✕» и подсказку «уйдёт, когда Claude освободится». Ввод: **Ctrl+Enter** в терминале НЕ подходит (терминал владеет клавиатурой) — поэтому отдельное поле ввода `#queue-input` появляется по **Ctrl+Q**, принимает текст, Enter — поставить в очередь, Esc — закрыть.

- [ ] Тесты: enqueue/remove/clear; Stop вбрасывает первый элемент и укорачивает очередь; Stop при пустой очереди ничего не пишет; вброс не происходит, если pty мёртв; close чистит очередь; несколько Stop подряд вбрасывают элементы по одному.
- [ ] RED → реализация → GREEN → UI → smoke → commit `feat: prompt queue with Stop-hook injection`.

### Task 2: history-index.js — индекс и поиск по транскриптам (TDD)

**Files:** Create `src/main/history-index.js`, `test/history-index.test.js`

**Interfaces:**
- `createHistoryIndex({ listProjects, readFileLines, stat, cache, now, maxResults = 50 })` — все ввод-вывод инжектируется.
  - `refresh({ force })` → пересобирает лёгкий индекс: для каждого `<project>/<sessionId>.jsonl` — `{sessionId, projectDir, cwd, mtime, size, firstUserText}` (первое сообщение пользователя, до 200 символов). Инкрементально: файлы с неизменившимися mtime/size берём из кэша.
  - `search(query, { limit })` → `[{sessionId, cwd, mtime, firstUserText, snippet, line}]` — потоково дочитывает только те файлы, что не отсеялись по индексу; регистронезависимо; поддержка нескольких слов (все должны встретиться в строке); snippet — фрагмент строки с подсветкой позиций (возвращать `{text, ranges:[[start,end]]}`, не HTML).
  - Устойчивость: битая строка JSONL — пропустить; файл исчез — пропустить; пустой запрос → `[]`.
- Кэш индекса — JSON-файл в userData; хранит версию схемы (при несовпадении — полный пересбор).

- [ ] Тесты на фикстурах во временной папке: индекс собирается; инкрементальность (неизменённый файл не перечитывается); поиск по одному и нескольким словам; регистронезависимость; битая строка не ломает; лимит результатов; snippet содержит верные диапазоны.
- [ ] RED → реализация → GREEN → commit `feat: history index and search over session transcripts`.

**Files:** Create `src/main/recipes.js`, `test/recipes.test.js`; Modify `ipc.js`, `preload.js`, `app.js`, `palette.js`, `dashboard.js` (или отдельный оверлей — на усмотрение), `app.css`

**Interfaces:**
- `recipes.js` (чистый): чтение/запись двух файлов в userData:
  - `prompts.json`: `[{id, title, text}]`, где в `text` допустимы плейсхолдеры `{{имя}}`.
    - `listPrompts()`, `savePrompt(p)`, `deletePrompt(id)`, `extractPlaceholders(text) → string[]` (уникальные, в порядке появления), `fillPrompt(text, values) → string`.

  - Битый файл → пустой список + пометка, НЕ перезаписывать молча (сохранить `.bak` перед первой записью поверх битого).
- Палитра: действия «Рецепт: <title>» (по одному на промпт) — при наличии плейсхолдеров показать мини-форму ввода, затем записать в pty активной вкладки; «Сохранить воркспейс…» (спросить имя, взять текущий состав вкладок); «Открыть воркспейс: <name>» (закрыть текущие вкладки и открыть состав профиля, со стаггером, как в restore).
