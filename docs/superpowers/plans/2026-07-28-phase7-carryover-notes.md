## Взять в работу

1. **Инъектируемый `execFile` в `ipc.js`** — тогда появятся тесты на реестр процессов,
   `killProcessTree` и `armKillWatchdog`. Сейчас эта логика держится на одном ручном
   наблюдении, а она несущая (без неё осиротевшие npx/gh/git копятся молча). Паттерн уже
   есть рядом: в `git-info.js`/`gh-info.js` `run` инжектируется.
2. **`classifyChecks` должен различать `CheckRun`/`StatusContext` по `__typename`**, а не по
   отсутствию поля `status`: `--json statusCheckRollup` возвращает `__typename` всегда.
3. **Нет теста на smoke-гейт** у `git:get`/`gh:repo`/`gh:global` — удаление `if (smoke) return null`
   нарушит Global Constraint и пройдёт зелёным.
4. **`GH_ERROR_TEXT` не знает кода `'failed'`** (это ДРУГАЯ карта, не та, что чинили в волне) —
   падает в общий «GitHub недоступен». Тот же класс, что и уже исправленный `LIMITS_ERROR_TEXT`.
5. **Нет теста на «странные» имена untracked-файлов** (пробелы, кириллица, ведущий дефис) через
   новый путь `--no-index`. Механизм безопасен по построению (`execFile` массивом, без `shell`,
   путь после `--`), но это непроверенный край, а не доказанный.
6. **Эвристика «показано 20, возможно больше»** даёт ложное срабатывание, когда открытых PR
   ровно 20. Инherent для подхода, задокументировано в коде; если захочется точности — считать
   отдельным запросом.
7. **Кэши `git-info`/`gh-info` без вытеснения** (Map по cwd) — ограничено числом папок за сессию.

## Из живой приёмки пользователем (28.07)

- **Бейдж PR со статусом `none` слишком неприметный.** У репозитория без настроенного CI
  бейдж красится в `--text-dim` и на фоне сайдбара пользователь его не нашёл с первого раза
  (пришлось подсказывать, куда смотреть). Семантически dim верен («проверок нет»), но
  практически это «невидимо». Предложение: для `none` использовать `--text-muted` вместо
  `--text-dim`, либо добавить бейджу фон `--bg-card` — тогда пилюля читается как элемент,
  а цвет по-прежнему кодирует статус проверок.
- Подтверждено вживую: панель показывает untracked-файл с содержимым (фикс работает);
  кольца лимитов и раздел GitHub отрисованы корректно.

## Мелочи, оставленные осознанно

- `+++`/`---` в диффе красятся как add/remove (как в `git diff --color`).
- Черновой PR с упавшими проверками показывается серым бейджем на вкладке, но красным в
  дашборде: `search prs` не отдаёт `isDraft`. Расхождение соответствует тексту плана.
- `PostToolUse` срабатывает на каждый вызов инструмента, а каждое хук-событие — это новый
  процесс `node scripts/cockpit-hook.js`: примерно вдвое больше процессов на ход Claude.
  Приемлемо для персонального инструмента, но помнить.
- Single-flight не различает `force`: пришедший во время полёта `force:true` присоединяется к
  текущему запросу (который и так свежий), а не стартует свой.

## Проверено и признано нормой

- Диффпанель — не оверлей: Escape-обработчиков не добавляет, оверлеи её корректно накрывают.
- `--no-index` действительно только читает: ни `add -N`, ни записи в индекс; бинарники
  отсеиваются по сентинелу `-\t-`; ограничение 50 файлов; пути передаются массивом без shell.
- Заголовок панели остаётся арифметически честным даже при одновременном срабатывании обоих
  ограничений (200 файлов и 50 диффов новых) — файлы строго разделены на «посчитанные» и «новые».
- 273/273 тестов, smoke чистый.
