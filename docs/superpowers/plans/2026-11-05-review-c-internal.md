## Группа N — сеть и эстафета (`ownership.js`, `net-server.js`, `broadcast.js`, `command-registry.js` + их тесты)

- **C2** `ownership.js`: `sizes` растёт на каждое переподключение браузера
  (ключ `c${nextClientId}`) — чистить размер клиента, который отключился и не
  является владельцем (владельца НЕ чистить: его размер нужен при возврате руля
  без нового размера). Тест: 100 переподключений не-владельцев → карта не растёт.
- **C3** `net-server.js`: `net:buffer`, `owner:claim`, `owner:get` обрабатываются
  мимо реестра, гард на них не зовётся. Нужен тест-инвариант: всё, что сервер
  перехватывает сам, — подмножество свободных (FREE) каналов `write-channels.js`;
  новый перехват пишущего канала → тест краснеет.
- **C4** `command-registry.js`: повторная регистрация канала молча перезаписывает
  обработчик → бросать ошибку (или явный отказ) при повторе; тест на настоящем
  реестре, не на фейковом `ipcMain`.
- **C5** `net-server.js`: белый список Host всегда с портом — на `port: 80`
  (и 443) браузер шлёт Host без порта → 403 на все WS-апгрейды. Принимать и
  вариант без порта для портов по умолчанию.
- **C6** `net-server.js`/`broadcast.js`: каждое событие сериализуется отдельно
  для каждого клиента → `JSON.stringify` один раз на событие.
- **C7** `net-server.js`: `reply` уходит и на кадры без `id` (ветки ошибок это
  гардят, основной путь — нет) → отвечать только при наличии `id`.
