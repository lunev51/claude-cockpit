# Carryover из финального ревью Фазы 4 → в Фазу 5

Источник: whole-branch review ветки phase4-attention (0c447b3..84d0371). Обе Important
(пустой Enter в peek принимал permission-промпт; фокус повисал на `<body>` после закрытия
peek) и пять однострочников закрыты фикс-волной 84d0371. Ниже — отложенное.

## Важно понимать про peek (не баг, а ограничение контракта Claude Code)

`waitingText` — это поле `message` хука Notification, а в реальном Claude Code это
однострочная фраза вроде «Claude needs your permission to use Bash», а НЕ пронумерованный
список вариантов. Спека §5.4 выполнена буквально, но `parseOptions` в бою будет почти
всегда возвращать пустой список: кнопки-цифры окажутся дремлющими, а в поповере будет
короткая фраза, а не «полный вопрос Claude». Живые проверки фазы использовали синтетический
POST на hook-bridge, поэтому парсер ни разу не встречался с настоящим промптом.
Что с этим делать в Фазе 5 (варианты, выбрать при планировании):
- читать хвост JSONL-транскрипта сессии и показывать в peek последние строки ответа Claude
  (там видно и вопрос, и варианты);
- либо честно переименовать peek в «быстрый ответ» и не обещать разбор вариантов.
В любом случае — проверить на РЕАЛЬНОМ permission-промпте перед доработкой.

## Взять в работу

1. **Утечка карт в `toasts.js`**: `workingSince`/`lastStatus` чистятся только на `dead`,
   но `manager.close()` инкрементит поколение до `kill()`, поэтому закрытая вкладка `dead`
   не эмитит — по две записи на закрытую вкладку остаются навсегда. Добавить
   `toaster.forget(tabId)` и звать из обработчика `tabs:close`.
2. **`Ctrl+R` внутри DevTools** снова открывает старую дыру: renderer перезагружается
   поверх живых вкладок main, `boot()` выполняется повторно, восстановление плодит второй
   набор pty, а старые остаются недостижимыми. Меню отключено, но F12 вернули осознанно —
   значит нужен предохранитель: либо блокировать reload (`webContents.on('will-navigate')`
   уже есть — проверить, ловит ли он reload; иначе `before-input-event` на Ctrl+R),
   либо делать `boot()` идемпотентным (переиспользовать уже открытые вкладки main).
3. **`waitingTabs` может разойтись с сайдбаром**: `app.js` добавляет в Set безусловно, а
   `tabs.js` при отсутствии строки молча выходит. На практике недостижимо (синхронный
   `tabStore.add` всегда опережает IPC), но инвариант лучше сделать структурным — считать
   бейдж из стора, а не из отдельного Set.
4. **`peekedTabId` не сбрасывается в `activateTab()`** (только в `closeTab` и авто-закрытии
   по статусу). Сейчас безопасно только потому, что `peek.update()/hide()` защищены
   собственным флагом `open`; при рефакторинге легко превратится в реальный баг.
5. **Позиция поповера — одноразовый снимок**: строка сайдбара уезжает при перегруппировке
   или скролле, поповер остаётся на месте. Косметика.
6. **`done`-таймер перезапускается на mid-turn permission-промпте** (`waiting → working`
   считается новым ходом). Спорно: пользователь, ответивший на промпт, скорее всего рядом.
   Зафиксировано как намеренное поведение, а не случайность.

## Не закрытые тестовые дыры (осознанно)

- У четырёх новых IPC-каналов (`attention:update`, `screenshot:paste`, `app:devtools`,
  `tab:activate`) нет автотестов на валидацию аргументов — в репо нет ipc-харнесса.
  Строить Electron-харнесс ради этого не стоит; помнить при добавлении новых каналов.
- Renderer (peek/palette/overlay) по-прежнему без DOM-тестов — проверяется живьём через CDP.

## Ручная приёмка Фазы 4 (за пользователем)

1. Свернуть окно, дождаться вопроса Claude → тост + бейдж с цифрой на иконке в панели задач
   (бейдж ни разу не был подтверждён глазами — только вызовом API).
2. Клик по тосту поднимает окно и переключает на нужную вкладку.
3. Клик по ждущей строке → peek; ответ уходит, фокус остаётся в исходной вкладке.
4. Ctrl+P → палитра; Ctrl+Shift+V со скриншотом в буфере → путь к PNG в промпте.
