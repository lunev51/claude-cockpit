## Технические контракты whisper (сняты с рабочего Companion)

- Сервер: `whisper-server.exe -m <model> -t <threads=6> -l ru --host 127.0.0.1
  --port <48753> -nt`; для CUDA-бекенда дополнительно `--no-flash-attn
  --no-fallback` (Pascal GTX 10xx: flash-attention без оптимизированных ядер
  тормозит энкодер в ~9 раз; temperature-fallback даёт редкие 10-15с провалы).
- Бекенды в порядке предпочтения: `vendor/whisper-cuda` → `vendor/whisper`
  (CPU). Провал старта одного → следующий. Готовность — поллинг `GET /`
  раз в 300 мс, дедлайн 20 с (модель small грузится секунды, large — дольше).
- Распознавание: `POST /inference`, multipart/form-data (`file` WAV +
  `response_format=json`), ответ `{text}`. Кириллица безопасна ТОЛЬКО в
  UTF-8-теле multipart — через argv whisper-cli на Windows приходит cp1251-
  мусор, поэтому HTTP-путь основной; CLI-фоллбэк без промпта.
- Убийство сервера: `proc.kill()` НЕ добивает процесс с загруженной моделью
  на Windows — контрольный `taskkill /PID <pid> /T /F` обязателен (правило
  проекта разрешает /F для helper-процессов в продакшн-коде). Exit-хендлер
  снимается ДО убийства, иначе его отложенное срабатывание затирает состояние
  нового сервера.
- Модель по умолчанию `large-v3-turbo-q5_0` (574 МБ, есть у пользователя),
  язык `ru`. Порт кокпита — **48753** (Companion живёт на 48752; оба могут
  работать одновременно).

## Архитектура

**`src/main/stt.js`** — порт Companion-модуля, переведённый на конвенцию
кокпита: фабрика `createStt({ spawnProc, httpRequest, fs, now, setTimer,
registerProcess, config, log })` → `{ transcribeWav(wavBuffer) →
Promise<string>, ensureServer(), dispose(), status() }`. Вся логика
(перебор бекендов, ready-поллинг, multipart, восстановление readyPromise
между итерациями) сохраняется 1-в-1, меняется только способ получения
эффектов. `registerProcess` — регистрация ребёнка в реестре процессов
runners.js (фаза 7): уборка на выходе тем же механизмом, что gh/git.

**Renderer:** `recorder.js`/`pcm-worklet.js` — как есть. В `app.js`:
- keydown/keyup правого Shift (`ev.code === 'ShiftRight'`) на window в
  capture-фазе; гард: запись НЕ стартует, пока открыт любой оверлей из
  overlayFlags() (голос в палитру/диалог — бессмыслица) и пока нет активной
  вкладки. Оверлей открылся ВО ВРЕМЯ записи → запись отменяется без
  отправки (тот же исход, что короткое нажатие).
- Отпускание раньше 300 мс — отмена (случайный Shift), WAV не отправляется.
- Индикатор: докрашивается существующая панель действий — во время записи
  видимый бейдж «🎤 запись…» (класс на #action-bar, токены v2), во время
  распознавания «🎤 …».
- Результат: `api.stt.transcribe(wav)` → текст → **тот же гард статуса
  writeCommandToTab, что у рецептов/слэш-кнопок** (вкладка в waiting →
  тост, текст НЕ отправлен) → `текст + \r` в pty активной вкладки. Пустой/
  пробельный результат → тост «не расслышал», ничего не отправлено.
  Внутренние переводы строк нормализуются той же normalizeForPty.

**IPC:** `stt:transcribe` (invoke, ArrayBuffer WAV → string), `stt:status`
(invoke → {available, backend, warm}). В smoke оба отвечают заглушкой без
спавна. Хендлеры — экспортируемые функции (паттерн gitGetHandler) + смоук-
гейт тесты.

**Конфиг (`config.js`, секция `stt`):** `{ stackRoots: [...дефолт выше],
model: 'large-v3-turbo-q5_0', language: 'ru', threads: 6, serverPort: 48753,
holdKey: 'ShiftRight', minHoldMs: 300 }`.

## Жизненный цикл сервера

Ленивый старт при ПЕРВОЙ записи (модель в памяти ~1 ГБ — не платим, если
сегодня не диктуем); дальше тёплый до выхода. Пока сервер грузится
(до 20 с на large), запись работает: WAV ждёт `ensureServer()`, индикатор
показывает «🎤 …». Сервер упал (exit) → следующая запись стартует его заново.
`dispose()` на teardown — рядом с nightWatch.dispose().

## Ошибки

- Стек не найден ни по одному пути → `stt:status.available=false`; первое
  нажатие Shift даёт ОДИН тост «Голосовой стек не найден (см. stt.stackRoots
  в конфиге)», дальше no-op до перезапуска.
- Оба бекенда не поднялись → тост с текстом ошибки, WAV отброшен.
- `/inference` не-200/таймаут (60 с) → один ретрай после перезапуска сервера,
  затем тост.
- Микрофон запрещён/отсутствует → тост, no-op.
- Никогда не бросать наружу; сбои — в лог main-процесса.

## Тестирование

`test/stt.test.js`, `node --test`, все эффекты фейковые: выбор стека по
кандидатам (первый валидный; ни одного → отказ); перебор бекендов CUDA→CPU
при провале старта; ready-поллинг с дедлайном; multipart-тело (границы,
UTF-8 кириллица в prompt-части НЕ через argv); один ретрай после перезапуска;
dispose снимает exit-хендлер до kill; smoke-гейты. Renderer (recorder,
Shift-обработка) — живая приёмка.

## Приёмка (руками)

1. Зажать правый Shift в активной вкладке → бейдж «🎤 запись…» → сказать
   фразу → отпустить → текст появился в терминале и отправился.
2. Короткое нажатие Shift (<300 мс) → ничего не произошло.
3. Диктовка во вкладку с открытым диалогом разрешения → тост, текст не ушёл.
4. Первый запуск за сессию: индикатор «…» пока грузится модель, потом текст
   доезжает (без потери WAV).
5. Companion запущен параллельно → оба работают (разные порты).

## Глобальные ограничения (как во всех фазах)

Никаких новых npm-зависимостей и нативных модулей (spawn готового exe — не
нативный модуль); чистые модули с инжекцией, тесты `node --test`; никогда не
бросать наружу; в smoke не спавнить процессы и не трогать userData; только
токены v2; комментарии по-русски; голый CR в pty запрещён — доставка через
существующие гарды.
