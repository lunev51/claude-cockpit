# Cockpit — кокпит для Claude Code (дизайн-спека)

Дата: 2026-07-26. Статус: утверждена (раскладка и архитектура — явно; остальные секции делегированы: «собирай, как считаешь правильным»).

## 1. Что это и зачем

Персональный «кокпит» для работы с Claude Code CLI на Windows 10: одно Electron-окно
вместо десятка терминальных вкладок. Три исходные боли:

1. Утренняя рутина: 10 × (открыть вкладку, cd, `claude`, `/resume`) → один запуск,
   всё восстановилось само, как вкладки браузера.
2. Нет обзора: не видно, в каком проекте Claude ждёт ответа → сайдбар со статусами,
   сортировка по срочности, уведомления.
3. Лимиты вслепую: `/usage` надо спрашивать руками → постоянные кольца 5-часового
   и недельного лимита + дашборд расходов по проектам.

База — дубликат рабочего Claude Companion (Electron 29 + node-pty prebuilt +
xterm.js 6, ConPTY-фиксы). Голос и VRM-аватар удаляются полностью.

### Не-цели

- Не GUI-чат поверх Agent SDK: внутри вкладки живёт настоящий неизменённый Claude CLI.
- Не командная/облачная работа, без телеметрии: всё локально.
- Не менеджер git-worktree (как Conductor/Pane); проект = папка, worktrees — забота Claude Code.
- Не переезд с Electron 29 (пребилды pty) и не переписывание на фреймворк: ванильный JS, как в Companion.

## 2. Утверждённые решения

| Решение | Выбор |
|---|---|
| Ядро | Гибрид: терминал (xterm + CLI) внутри, GUI-обвязка вокруг |
| Модель вкладок | Браузерная: воркспейс персистентен, restore при запуске |
| Объём | «В — Максимум» (полный список в §3) |
| Раскладка | B «Claude Desktop»: левый сайдбар сессий, отсортированный по срочности; мокапы в `.superpowers/brainstorm/465-1785067468/content/layout-b-refined.html` |
| Статусы | Только из хуков Claude Code, не из парсинга ANSI-вывода |
| Resume | `claude --resume <session-id>` (id из SessionStart-хука); `--continue` не использовать (берёт лишь последнюю сессию папки) |

## 3. Функциональный объём (v1 = «Максимум»)

Ядро:

1. Вкладки-проекты с браузерным restore (манифест воркспейса, атомарная запись при каждом изменении).
2. Авто-resume по session-id + экран «восстановить N сессий? [все/выборочно]» + поочерёдный спавн (стаггер ~2 с).
3. Ghost buffers: сериализация буфера xterm (serialize addon) периодически и на Stop-хук; после ребута — мгновенный вчерашний скроллбек приглушённым цветом до оживания pty.
4. Статусы вкладок: работает / ждёт тебя / готово / завис / мёртв + динамический подзаголовок («Editing feed.py…») из PreToolUse/PostToolUse.
5. Сайдбар с группировкой по срочности: Ждут → Работают → Тихо/ошибки → Завершённые (свёрнуто). Пин проекта.
6. Кольца лимитов: 5-часовое окно + неделя, обратный отсчёт до сброса, pacing («41% при норме 55% — запас»), доля Opus недели.
7. Умные уведомления Windows: только для не-активной вкладки/окна без фокуса; клик → фокус нужной вкладки; overlay-бейдж «сколько ждут» на иконке таскбара; 3 типа событий (готово / ждёт ввода / ошибка).
8. Кнопка «подключить проект»: сама вписывает хуки + statusline в `.claude/settings.json` проекта (merge).
9. Дашборд: 4 карточки (расход / сессии / токены / burn rate с прогнозом «хватит до HH:MM»), бар-чарт по дням (div-бары, пресеты 7д/30д/всё), таблица по проектам с breakdown по моделям (Opus подсвечен) и cache read/write.
10. Дизайн-система Claude-dark (§7).

Поверх ядра:

11. Peek-попап (Space/клик на строке сайдбара): последний вопрос Claude + ответ цифрой или текстом прямо в pty чужой вкладки, не переключаясь.
12. Очередь промптов: ввод при занятом Claude встаёт в видимую редактируемую очередь, вбрасывается по Stop-хуку.
13. Command palette (Ctrl+P): fuzzy-действия (перейти к проекту, resume всё, перезапуск сессии, дашборд, поиск, «send prompt to…») + Ctrl+1..9 по закреплённому порядку вкладок.
14. Детект зависаний: статус working без вывода pty > N мин (деф. 5) или pty умер → «завис» + кнопка «перезапустить на месте» (`--resume` того же id, раскладка не трогается).
15. Вставка скриншотов Ctrl+Shift+V: clipboard → PNG в temp-папку проекта → путь печатается в pty (обход битой вставки картинок в ConPTY).
16. Подпись вкладок: имя = первое user-сообщение сессии из JSONL (fallback: имя папки); после resume опционально авто-«recap: что сделано, что осталось».
17. Diff-панель per-вкладка (Ctrl+G): git status + diff рабочей папки, обновление по PostToolUse (дебаунс) и таймеру; подсветка.
18. Глобальный поиск (Ctrl+Shift+F): SQLite FTS5 по всем JSONL-транскриптам всех проектов; результат → «открыть вкладку с `--resume <id>`».
19. «Send prompt to…»: один промпт чекбоксами в несколько проектов (например `/compact` во все при тающем лимите).
20. Заморозка вкладки: kill pty (освободить RAM/ConPTY), session-id сохранён, «разморозить» = `--resume`; мини-монитор RAM/CPU процессов claude (pidusage) в тултипе вкладки.
21. Split view: Ctrl+клик по строке сайдбара → второй терминал рядом (макс. 2 панели, без drag-and-drop сетки).
22. GitHub-панель (добавлено по запросу 26.07 после Фазы 1): данные через `gh` CLI
    (уже авторизован; spawn `gh ... --json` из main, поллинг 2–3 мин + ручной refresh).
    (а) бейдж PR на вкладке проекта — по паттерну Agent View: жёлтый «checks идут»,
    зелёный «прошли», красный «упали», фиолетовый «merged» — для PR текущей ветки;
    (б) раздел «GitHub» в дашборде: открытые PR по всем проектам кокпита с CI/ревью-статусом,
    назначенные issues, лента уведомлений (`gh api notifications`); клик — в браузер.
    Проекты без GitHub-remote просто не показываются; офлайн → stale-пометка как у OAuth-слоя.

Отложено (v2+): библиотека агентов, чекпоинты файлов (есть /rewind), MCP-менеджер, редактор CLAUDE.md (в v1 — просто кнопка «открыть в блокноте»), Summary-лента параллельно терминалу, планировщик `claude -p`-прогонов.

Добавлено по запросу 27.07 (вдохновение — Warp), очередь после v1:

23. Нижняя панель действий: эволюция статус-бара — кнопки (дашборд, diff, палитра, скриншот,
    микрофон) + индикаторы; раскладка и иконки в стиле Warp, палитра наша.
24. Файловый проводник: сворачиваемое дерево файлов проекта активной вкладки;
    клик — открыть системно, Ctrl+клик — вставить путь в промпт терминала.
25. Голосовой ввод (ТОЛЬКО ввод, без TTS/аватара). Ресёрч 27.07: «хороший» голос Warp —
    это Wispr Flow (облачный движок: стриминговая транскрипция, LLM-полировка, 100+ языков).
    План: (а) сначала попробовать Wispr Flow для Windows как СИСТЕМНУЮ утилиту — работает

26. Кнопки-шорткаты слэш-команд на панели действий (уточнено 27.07): нажатие пишет
    команду + Enter в pty активной вкладки. Настраиваемый список в конфиге; дефолт:
    `/remote-control` (продолжить сессию с телефона через claude.ai), `/compact`,
    `/usage`, `/resume`. Реализация тривиальна (write в pty), войдёт в фичу 23.

Ресёрч Warp 27.07 — что ещё стоит забрать (отфильтровано: блоки команд, IDE-редактор
ввода, автодополнения и Warp Drive не переносятся — у нас в терминале живёт TUI Claude,
а не шелл; облако/команды не нужны):

27. **Библиотека промптов** (аналог Warp Workflows — самая ценная кража). Сохранённые
    параметризованные промпты с плейсхолдерами: «прогони тесты и почини падения»,
    «отревьюй мои изменения», «обнови зависимости в {{пакет}}». Хранение — YAML/JSON в
    `~/.cockpit/prompts/`, вызов из палитры (Ctrl+P) и кнопкой на панели действий;
    при наличии плейсхолдеров — мини-форма ввода, затем write в pty активной вкладки.
    Комбинируется с «send prompt to…» (§sleepers): один рецепт в несколько проектов.
28. **Именованные воркспейсы** (аналог Launch Configurations). Манифест (§5.1) уже хранит
    состав вкладок — расширить до нескольких профилей: «работа», «клиент», «пет-проекты»;
    переключение из палитры (закрыть текущие вкладки → восстановить состав профиля).
    Дёшево поверх готового манифеста.
29. **Навигатор по ходам** (переосмысленные Warp Blocks). Блоки команд нам недоступны,
    но хуки дают границы ходов: UserPromptSubmit = начало, Stop = конец. Кокпит помечает
    позиции в буфере xterm и даёт Alt+↑/↓ — прыжок к предыдущему/следующему ходу,
    плюс «скопировать весь ход». Даёт навигацию по длинной сессии, которой нет
    ни в CLI, ни у конкурентов.
30. **WebGL-рендер для скорости** (Warp хвалится 60fps на GPU). У нас аддон есть, но
    выключен из-за артефактов ConPTY с ghost-подсказками (Фаза 1). Пере-проверить на
    актуальном xterm 6: включать только активной вкладке (лимит WebGL-контекстов),
    фоновые — canvas. Заметно при больших выводах и 6 вкладках.

## 4. Архитектура

### 4.1 Main-процесс (`src/main/`)

| Модуль | Отвечает за | Зависит от |
|---|---|---|
| `sessions.js` | tabId → {pty, cwd, sessionId, status, queue, frozen}; машина статусов; стаггер-спавн; детект зависаний | `pty.js` |
| `workspace.js` | манифест воркспейса (вкладки, порядок, активная, session-id, пути ghost-буферов, пины); атомарная запись temp+rename на каждое изменение + дебаунс 500 мс | — |
| `hook-bridge.js` | HTTP-сервер на 127.0.0.1:<порт из конфига>: POST /event от хуков (SessionStart/Stop/Notification/PreToolUse/PostToolUse); маршрутизация по `session_id` из payload хука → tabId; для ещё не привязанной вкладки (до SessionStart) — по cwd среди непривязанных | — |
| `connector.js` | «подключить проект»: merge хуков + statusline в `.claude/settings.json` проекта; идемпотентно; маркирует свои записи комментарием-ключом | `hook-bridge` |
| `usage.js` | 3 слоя (§5.3); один OAuth-поллер на приложение; кэш в SQLite | `db.js` |
| `db.js` | better-sqlite3: workspace-снапшоты, usage-кэш (TTL 10 мин), FTS5-индекс транскриптов (инкрементальная индексация по mtime) | — |
| `git-diff.js` | spawn `git status --porcelain` + `git diff` per проект, дебаунс | — |
| `screenshot.js` | clipboard.readImage → PNG в `<проект>/.cockpit-shots/` (гитигнорится), возврат пути | — |
| `notify.js` (из Companion) | тосты + overlay badge + правило «не уведомлять о том, на что смотришь» | — |
| `pty.js`, `config.js`, `paths.js` (из Companion) | без изменений (pty: + запуск с env-меткой COCKPIT_TAB_ID) | — |

IPC: все каналы адресные (`term:data`, `term:input`, `tab:status`, … несут `tabId`). Preload — тонкий, как сейчас.

## 5. Потоки данных

### 5.1 Жизненный цикл вкладки

Новая: «+» → диалог папки (или recent из ~/.claude/projects) → `connector` дописывает хуки
→ spawn pty `claude` → SessionStart-хук POST-ит session-id → манифест обновлён.
Restore: старт приложения → чтение манифеста → экран restore (по умолчанию «все», Enter)
→ ghost-буферы вливаются мгновенно → спавн `claude --resume <id>` по одному со стаггером
→ по первому выводу pty ghost-плашка гаснет.
Закрытие вкладки ≠ удаление сессии: session-id остаётся в манифесте («Завершённые»), можно переоткрыть.

### 5.2 Машина статусов

```
spawn → working
Notification-хук (permission/question) → waiting   (текст вопроса сохраняется для peek)
Stop-хук → done  (если очередь непуста → вброс следующего → working)
PreToolUse → working + подзаголовок из tool_name/аргументов
нет вывода pty N мин при working → stuck
pty exit неожиданно → dead (кнопка перезапуска)
```

Статус меняет: строку сайдбара, бейдж вкладки, overlay-счётчик, шлёт уведомление (по правилам §3.7).

### 5.3 Лимиты и расходы (3 слоя, иерархия «official > estimate»)

1. **Statusline-tee (official, per-сессия, push).** `connector` прописывает statusline-команду
   `cockpit-statusline.ps1`, которая (а) рисует обычный статуслайн, (б) пишет полученный
   stdin-JSON (rate_limits 5h/7d, cost, context_window, session_id) в
   `%LOCALAPPDATA%\Cockpit\statusline\<session>.json`. Кокпит следит за папкой (fs.watch).
2. **OAuth-поллер (official, глобальный, pull).** GET `api.anthropic.com/api/oauth/usage`,
   токен из `~/.claude/.credentials.json` (только чтение, рефреш не делаем), заголовки
   Bearer + `anthropic-beta: oauth-2025-04-20` + `User-Agent: claude-code/<ver>`.
   Интервал 240 с; при 429/офлайне — последнее значение с пометкой «stale». Единственный
   слой, видящий общий пул (включая claude.ai-чат).
3. **ccusage data-loader (estimate, разбивки/история).** npm-библиотека парсит JSONL
   `~/.claude/projects/**`; агрегаты по проектам/моделям/дням, burn rate, cache r/w;
   кэш в SQLite TTL 10 мин; пересчёт лениво при открытии дашборда + фоновый на таймере.
   В UI помечено «estimate», в лимиты не конвертируется.

Кольца сайдбара питаются слоями 2→1 (fallback), дашборд — слоем 3 (+ официальные сверху).

### 5.4 Peek / очередь / palette / поиск

Peek: waiting-статус хранит последний текст Notification; попап пишет ответ в pty нужного
tabId (`\r`-терминированный или цифра). Очередь: массив строк в манифесте (переживает
рестарт); вброс по Stop. Palette: статический реестр действий + fuzzy (простой скоринг,
без библиотек). Поиск: FTS5-запрос → сниппеты → действие «resume в новой вкладке».

## 6. Отказоустойчивость

| Отказ | Поведение |
|---|---|
| pty умер / Claude крашнулся | статус dead, ghost-буфер остаётся, кнопка «перезапустить» (`--resume`); не авто-рестартить (может быть намеренный exit) |
| `--resume` не нашёл сессию | fallback: предложить `--continue` в этой папке или новую сессию; вкладка не удаляется |
| Хуки молчат (проект не подключён) | статус «серый» + подсказка «подключить проект»; терминал работает как обычный |
| OAuth 429/сеть/смена формата | стеле-деградация: последние данные + пометка stale; слой 1/3 продолжают работать |
| Манифест побился | хранить последние 5 снапшотов (`workspace.json.1..5`), брать свежий валидный; в худшем случае — скан ~/.claude/projects и пересборка списка |
| claude.exe не найден из GUI | индикатор в титлбаре + ручной выбор пути (resolveCommand уже есть) |
| ccusage-парсинг упал на файле | скип файла, лог, остальное считается |
| 6+ вкладок → RAM | стаггер-спавн, WebGL только активной, «заморозка» вкладок; pidusage-монитор подсказывает кого морозить |
| Обновление Claude Code сломало контракт | статусы деградируют в «серый», терминал не страдает (главный инвариант: кокпит никогда не мешает работе CLI) |

## 7. Дизайн-система (v2 от 27.07: нейтральный чёрный в духе Warp)

РЕШЕНИЕ 27.07: пользователь выбрал вариант E — вся шкала НЕЙТРАЛЬНАЯ (R=G=B), как
`#181818` у Warp. Прежняя тёплая гамма Claude (hue 40–70) читалась «коричнево-серой»;
она сохранена ниже как v1 для истории. Геометрия и типографика — тоже по Warp:
жёсткие радиусы, плотность, Inter + DM Mono, хайрлайны, никаких теней и серифов.

Токены v2 (`tokens.css`):

- Поверхности: окно и терминал `#0F0F0F`, панели/сайдбар `#141414`, карточки/инпуты
  `#1E1E1E`, hover `#2A2A2A`; подложка «ждёт тебя» `#231A16`.
- Границы: `#2A2A2A`, мягкая `#333333`. Elevation — ступени цвета + хайрлайны, теней нет.
- Текст: основной `#E8E8E8`, приглушённый `#9E9E9E`, слабый `#8A8A8A`.
- Акцент: терракота `#D97757` — ТОЛЬКО «ждёт тебя» (пульс + левая кромка 2px строки) и
  главные CTA; hover `#A9583E`. Единственный хроматический акцент в интерфейсе.
- Статусы — ANSI-палитра Warp default_dark: working `#86c1b9` (cyan), done `#a1b56c`
  (green), stuck `#f7ca88` (yellow), dead `#ab4642` (red), idle `#8A8A8A`.
  Прогресс лимитов: green → yellow (>60%) → red (>85%).
- Типографика: UI — Inter 400/500 (серифов НЕТ, включая титлбар), бандлится локально (woff2,
